1. AUDIT TECHNIQUE DES 9 DISPOSITIFS DE SÉCURITÉ

1 Hachage des Mots de Passe bcryptjs (Cost 10)

Mots de passe chiffrés de manière irréversible. Aucun mot de passe en clair dans la base de données.

2 Tokens Cryptographiques jsonwebtoken (JWT)

Authentification par jetons signés avec JWT_SECRET. Expiration et vérification automatique à chaque requête.

3 Contrôle d'Accès par Rôles role.middleware.ts

Fonctions sensibles réservées exclusivement aux rôles admin et super_admin.

4 Protection Anti-Brute Force rateLimit.middleware.ts

Limitation stricte à 15 tentatives max par 15 minutes par adresse IP sur la connexion et l'inscription.

5 Alertes de Connexion E-mail email.service.ts

Notification instantanée envoyée par e-mail lors de chaque connexion réussie avec horodatage précis.

6 Protection Anti-Injection SQL Prisma ORM

Requêtes de base de données 100% paramétrées neutralisant toutes les injections SQL (SQLi).

7 Filtrage des Origines Réseau CORS Policy

Rejet systématique des requêtes provenant de domaines non autorisés.

8 Validation des Données Zod Schemas

Validation stricte des types, formats et longueurs de données avant tout traitement serveur.

9 Isolation des Secrets .env & .gitignore

Stockage étanche des variables d'environnement hors des dépôts publics GitHub.

2. GUIDE PRATIQUE DE GESTION PAR SALOMON (SUPER ADMIN)

⚙️ Personnalisation des paramètres de sécurité :

1. Clé Secrète JWT : Modifiez JWT_SECRET dans backend/.env.
2. Anti-Brute Force : Ajustez max: 15 dans backend/src/middlewares/rateLimit.middleware.ts.
3. Envois d'E-mails SMTP : Configurez SMTP_USER et SMTP_PASS dans backend/.env.
4. Origine CORS Réseau : Restreignez CORS_ORIGIN dans backend/.env.

3. PROCÉDURE DE MISE À JOUR & DÉPANNAGE (RÉSOLUTIONS DE SOUCIS)

🚀 Procédure officielle pour effectuer une mise à jour du site :

Étape 1 (Tests locaux) : Lancez npm run dev --prefix backend (port 5000) et npm run dev --prefix frontend (port 5173).
Étape 2 (Vérification build) : Vérifiez la compilation sans erreur avec npm run build --prefix backend et npm run build --prefix frontend.
Étape 3 (Push GitHub) : Exécutez git add . ➔ git commit -m "Description" ➔ git push origin main. Le site en ligne sera automatiquement mis à jour.

🛠️ Guide de Résolution des 5 Soucis Techniques Fréquents :

Souci 1 : E-mails de bienvenue ou de connexion non reçus
Solution : Vérifiez dans backend/.env que SMTP_USER contient votre e-mail et que SMTP_PASS contient le mot de passe d'application Gmail à 16 caractères (sans espaces).
Souci 2 : Erreur 401 Unauthorized ou perte d'accès Admin
Solution : Le jeton JWT a expiré. Cliquez sur Déconnexion dans l'Espace Membre puis reconnectez-vous avec le compte admin salomon.admin@ajtes.td pour régénérer un token frais.
Souci 3 : Les nouvelles modifications du site ne s'affichent pas
Solution : Le navigateur a gardé l'ancien cache. Faites un rafraîchissement forcé avec les touches CTRL + SHIFT + R (ou CTRL + F5).
Souci 4 : Erreur 429 Too Many Requests
Solution : Blocage automatique anti-brute force déclenché. Le déblocage s'effectue automatiquement après 15 minutes d'attente.
Souci 5 : Erreur lors du git push (Demande de mot de passe GitHub)
Solution : GitHub exige un Personal Access Token (PAT). Générez-le dans GitHub ➔ Settings ➔ Developer Settings ➔ Personal Access Tokens (classic) avec la coche repo, et utilisez-le comme mot de passe.
