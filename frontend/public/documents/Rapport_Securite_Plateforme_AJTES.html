🟢 CHAPITRE 1 : COMPRENDRE LA SÉCURITÉ DE VOTRE SITE (EXPLIQUÉE SIMPLEMENT)

Voici les 9 protections de votre site expliquées avec des images simples pour bien retenir :

1 Le Coffre-Fort des Mots de Passe bcryptjs

Explication simple : Vos mots de passe ne sont pas écrits en lisible. Le système les transforme en un code secret indéchiffrable. Même si un pirate volait la base de données, il ne pourrait pas lire votre mot de passe.

2 Le Badge Numérique d'Accès JWT (Tokens)

Explication simple : Quand vous vous connectez, le site vous donne un badge électronique temporaire. À chaque clic, votre navigateur montre ce badge pour prouver que c'est bien vous.

3 Le Contrôle des Portes d'Accès RBAC (Rôles)

Explication simple : Les visiteurs simples ont accès aux pages publiques. Seul votre compte (Salomon Admin) possède la clé pour ouvrir la porte de l'Espace Administration.

4 L'Alarme Anti-Intrusion (Blocage Automatique) Rate Limiting

Explication simple : Si quelqu'un essaie de deviner votre mot de passe plus de 15 fois en 15 minutes, l'alarme sonne et bloque cette personne pendant 15 minutes.

5 L'Alerte E-mail Instantanée email.service.ts

Explication simple : À chaque fois qu'un admin se connecte, le site vous envoie immédiatement un e-mail pour vous avertir avec l'heure exacte.

6 Le Mur Anti-Code Malveillant Prisma ORM

Explication simple : Empêche les pirates d'injecter du faux code SQL dans la base de données à travers les formulaires.

7 La Barrière de Domaine CORS Policy

Explication simple : Seul votre site web officiel a le droit d'envoyer des demandes à votre serveur. Les sites étrangers sont refusés.

8 Le Contrôleur des Formulaires Zod Schemas

Explication simple : Vérifie que chaque case remplie par un utilisateur contient des données valides (e-mail correct, texte propre).

9 Le Fichier Secret Cache-Clés .env

Explication simple : Toutes vos clés et mots de passe secrets restent enfermés dans un fichier cache `.env` qui n'est jamais publié sur GitHub.

🟡 CHAPITRE 2 : COMMENT FAIRE UNE MISE À JOUR DU SITE (PAS À PAS)

Suivez exactement ces 4 étapes simples lorsque vous voulez modifier quelque chose sur le site :

💻 ÉTAPE 1 : Lancer le projet sur votre ordinateur pour tester
Ouvrez le terminal dans VS Code et tapez ces 2 commandes pour voir vos modifications en direct : npm run dev --prefix backend (Dans un 2ème terminal) : npm run dev --prefix frontend Ouvrez ensuite votre navigateur sur : http://localhost:5173
🔍 ÉTAPE 2 : Vérifier que le code n'a pas d'erreur
Avant d'envoyer votre travail en ligne, vérifiez que tout compile proprement avec : npm run build --prefix backend npm run build --prefix frontend Si le terminal affiche "built in X.XXs", cela veut dire que votre code est parfait !
🚀 ÉTAPE 3 : Envoyer les modifications sur GitHub (En ligne)
Tapez exactement ces 3 commandes dans le terminal l'une après l'autre : git add . git commit -m "Mise à jour : votre message ici" git push origin main Félicitations ! Vos modifications sont automatiquement publiées sur Internet.

🔴 CHAPITRE 3 : GUIDE DE DÉPANNAGE FACILE (EN CAS DE PROBLÈME)

Si un bogue survient, gardez votre calme et suivez la solution correspondante ci-dessous :

❌ Cas 1 : "Je ne reçois pas les e-mails de notification sur mon Gmail"
Solution Pas à Pas : 1. Ouvrez le fichier backend/.env.
2. Mettez votre e-mail : SMTP_USER=association.ajtes@gmail.com.
3. Créez un Mot de passe d'application Gmail (16 lettres) dans votre compte Google ➔ Sécurité.
4. Collez ce code dans SMTP_PASS=votre_code_16_lettres.
5. Redémarrez le serveur backend.
❌ Cas 2 : "Je n'arrive plus à cliquer sur les boutons Admin (Erreur 401)"
Explication : Votre badge numérique (token JWT) a expiré pour votre sécurité.
Solution Pas à Pas :
1. Cliquez sur le bouton Déconnexion sur le site.
2. Reconnectez-vous avec votre adresse admin (salomon.admin@ajtes.td).
3. Vous aurez immédiatement un nouveau badge valide pour travailler.
❌ Cas 3 : "J'ai modifié le code mais rien ne change sur mon écran !"
Explication : Le navigateur a gardé l'ancienne version en mémoire cache.
Solution Pas à Pas :
Sur votre clavier, appuyez en même temps sur : CTRL + SHIFT + R (ou CTRL + F5). La page se rafraîchira avec la nouvelle version.
❌ Cas 4 : "Le site m'affiche Erreur 429 Trop de requêtes !"
Explication : L'alarme anti-brute force a détecté trop de clics/connexions rapides.
Solution Pas à Pas :
Attendez 15 minutes sans toucher à rien. Le système vous débloquera automatiquement.
❌ Cas 5 : "Git refuse mon git push et me demande un mot de passe !"
Explication : GitHub n'accepte plus les mots de passe de compte simples.
Solution Pas à Pas :
1. Allez sur GitHub.com ➔ Votre photo ➔ Settings ➔ Developer Settings.
2. Personal Access Tokens ➔ Tokens (classic) ➔ Generate new token.
3. Cochez la case repo et copiez la clé.
4. Collez cette clé dans le terminal quand il vous demande le mot de passe.
